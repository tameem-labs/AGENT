# CHANGE MANAGEMENT

For any change affecting invariants, contracts, security, boundaries or core architecture:

1. Reason.
2. Affected components.
3. Risk/impact.
4. Explicit decision.
5. Record ADR/change.
6. Version affected docs if needed.
7. Implement.
8. Test.
9. Update docs.
10. Update PROGRESS.md.

Never silently weaken safety, authorization, verification or hard-stop behavior for convenience.
